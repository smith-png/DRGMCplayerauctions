## 2024-03-24 - [IDOR in Auction Bidding API]
**Vulnerability:** The `/api/auction/bid` endpoint had an Insecure Direct Object Reference (IDOR) / Authorization bypass vulnerability. A `team_owner` (or even a `viewer` since the route only required `authenticateToken` middleware but no role-specific checks or specific data-ownership checks in the controller) could arbitrarily pass any `teamId` in the request body. The system would then place a bid using the funds of the target team instead of the requester's team.
**Learning:** Middleware like `authenticateToken` only verifies who the user is, but the controller must still verify if the user has authorization over the specific resource (e.g. `teamId` provided in the payload).
**Prevention:** In API endpoints that perform actions on behalf of a specific user or team, always enforce authorization at the object level by comparing the user's details from the token (e.g., `req.user.team_id`) against the resource ID being manipulated (e.g., `teamId` from the request body).
