## 2024-05-24 - IDOR Vulnerability due to Missing JWT Claim and Error Info Leakage
**Vulnerability:** Found a High severity IDOR vulnerability where users could place bids on behalf of other teams by providing arbitrary `teamId` in the request body because their JWT token lacked `team_id` claims, and authorization checks were missing in the controller. Also found instances of internal application/database errors being directly leaked to the client via `details: error.message` in error responses.
**Learning:** The `authenticateToken` middleware only validates JWT validity but not resource ownership or fine-grained authorization. Relying on request body input (`teamId`) for sensitive actions like budget deductions without explicit validation against the authenticated user's database records is insecure. Returning raw internal error details to the frontend poses an information leakage risk and must be avoided.
**Prevention:** Always validate that the authenticated user owns or is authorized to interact with the resource specified in the request input (e.g., verifying `req.user`'s actual `team_id` against the input `teamId` via a database query when the claim is missing from the JWT). Never expose raw `error.message` or stack traces in HTTP response JSON bodies; log them server-side instead and return generic, safe messages to the client.
